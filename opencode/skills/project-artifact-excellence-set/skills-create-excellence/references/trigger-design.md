# Trigger Design Checklist and Examples

## Goals
Maximize true-positive rate for intended use cases while minimizing false positives. The description is the only always-visible trigger surface.

## Checklist (mandatory before finalizing description)
1. List 5–10 concrete positive user utterances that must activate the skill.
2. List 5–10 negative utterances that must not activate it.
3. Ensure description contains distinctive keywords and scenarios from the positive set.
4. Avoid overly broad verbs alone (create, make, help) without domain anchors.
5. Include both “what” and “when”.
6. Keep under 1024 characters, plain scalar, no colon-space, no angle brackets.
7. Mentally simulate activation on the positive and negative lists. Adjust until precision and recall are high.
8. Prefer specific compound phrases over single generic words.

## Positive Pattern Examples (illustrative)
- “Create an exceptional skill for PDF form filling with full validation and human-factors checks”
- “Build a complete plugins set for multi-agent orchestration including contracts and versioning”
- “Upgrade this skill to excellence level with measurable metrics and composition support”
- “Generate agent specification with success criteria, failure modes and evaluation protocol”

## Negative Pattern Examples (should not trigger)
- “Write a Python for-loop”
- “Explain how recursion works”
- “Summarize this article”
- “What is the capital of France”

## Anti-Patterns in Descriptions
- Vague: “Helps with skills”
- Missing when: “Creates high-quality skills”
- Colon-space or quotes that force invalid YAML
- Leftover TODO or placeholder text
- Overly long lists that dilute signal

## Testing Protocol
After writing the description, re-run the positive/negative lists. Record hit rate. Iterate until ≥90% true positive and ≤10% false positive on the test set. Document the test set in references if the skill is complex.


## Feedback-Loop Use
When a normalized audit event maps to a possible trigger gap, evaluate the actual failed positive and negative utterances rather than editing the description from a broad finding label. Keep a dated, representative regression set; do not optimize recall at the expense of unrelated-task false positives. Skill feedback requests are generated by `scripts/process-audit-feedback.py`; they are proposals only and do not edit this skill automatically. Follow `../../shared/references/feedback-loop.md`.
